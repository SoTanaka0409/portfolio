作品

Skybound Slayer

個人制作1〜2か月C++ / DxLib / Effekseer

動画が表示されないときは、YouTubeで開く

どんなゲーム
敵を倒して資金を集め、キャラクターを強化して、ボスに挑む3DアクションRPG。
作った理由
就職活動用に、自分の基礎力を見せられる作品を作りたかったため。
担当
企画、設計、実装（当たり判定、ステート管理、メモリ管理）。修正点は先生とAIに相談。
苦労①：動きの管理が複雑に if-elseだけで作ると条件が絡み合いました。動きを状態ごとに分けてタグで分類すると、エラーが減り、コードも減りました。
苦労②：処理落ちとフリーズ 敵が増えると重くなり、フリーズしました。解放漏れと解放後の参照を整理して、フリーズは起きなくなりました。

チーム制作（5人）2か月リーダーC++17 / DxLib / Effekseer

どんなゲーム
UFOで牛をビームで捕まえて、ハイスコアを目指す3Dアクション。学校の課題として、同じ学校の4人と制作。
担当
チームリーダー、メインプログラマー。共通基盤（シーン管理・オブジェクト管理）、当たり判定の基盤、牛のAI。友人が当たり判定の調整と牛のAIの一部を担当。
苦労：時間が足りなくなった 見積もりが甘く、仕様変更も多い状況でした。タスクを絞り、意見は期限を確認して納得してもらい、Excelで毎日の作業をまとめて、納期内に提出しました。

Spell Burst

個人制作1か月C++ / DxLibAI活用を学ぶための作品

動画が表示されないときは、YouTubeで開く

どんなゲーム
低速移動で弾の隙間をすり抜ける、弾幕アクション。機体は3タイプ、難易度は3段階。
作った理由
AIの上手な使い方を学ぶため。Skybound Slayer のあとに制作。
自分で作成
ゲームの仕様（機体、必殺技、難易度、オート連射、低速移動、流れ）。
AIが作成
ボスの行動管理、弾の軌道計算、バリア、色相の処理、イラスト、音楽、コードのコメント。AIが作ったボスのコードは、仕組みをまだ十分に読めておらず、今後の課題です。
AIの使い方 「動いている部分には触らない」というルールを決め、コードの添削や、自分で作ったことのない処理を任せました。

技術とAIの使い方

自分で書いたもの

  • C / C++（DxLib、Effekseerを使った3Dゲーム制作）
  • C#（授業での制作と、2Dゲーム）
  • CSVへのデータの追加
  • Git / GitHub（mainと作業用ブランチを分けて管理）

AIを使って作ったもの

  • Python、Web技術（PHP・SQL・JavaScript・HTML/CSS）
  • 各作品の画像・音楽
  • Spell Burst のボスの動き、弾の軌道、バリア
  • CSVとタスク管理表の基本の形（そのあと、必要な情報を自分で追加）
  • ゲーム制作用プロンプト、自分専用の就職サポートツール
  • ゲームのコードの添削（改善点の指摘）
  • ソースコードのコメント（Doxygen形式）

AIは、改善点を出してもらう、自分では作ったことのない処理を作ってもらう、という使い方をしています。AIが作った部分は、仕組みを理解して説明できるようにすることが今後の課題です。
